## 1. 需求分析

### 1.1 核心功能梳理

| 功能模块 | 当前实现 | 需求差距 |
|---------|---------|---------|
| 城市选择 | 6城市静态数据 | 使用 amap-lbs-skill 动态获取城市POI |
| 时间选择 | Flatpickr日期时间 | 已实现，可扩展 |
| 偏好输入 | 文本描述+关键词匹配 | 缺乏深度偏好理解 |
| 路线生成 | 随机算法 | 使用 amap-lbs-skill 路径规划 + Deepseek AI 优化 |
| 地图展示 | 高德地图标记+连线 | 使用 amap-jsapi-skill 增强交互 |
| AI输出 | 打字机效果模拟 | Deepseek API 真实LLM生成 |
| 用户偏好 | 无 | 需增加登录系统持久化偏好 |

### 1.2 用户场景分析

```
用户场景1: 周末出游
  输入: "北京, 周末2天, 亲子游, 孩子6岁"
  需求: 适合儿童的项目, 时间紧凑, 避免排队

用户场景2: 出差顺便游玩
  输入: "上海, 下午会议结束18:00, 想要休闲+美食"
  需求: 晚间限定, 高效串联, 避开高峰

用户场景3: 深度文化游
  输入: "西安, 3天, 历史爱好者, 不喜欢人多"
  需求: 小众路线, 讲解详细, 避开网红打卡点

用户场景4: 美食之旅
  输入: "成都, 2天, 吃货, 不想排队"
  需求: 地道美食, 排队预测, 替代方案
```

### 1.3 当前实现与需求差距

| 差距维度 | 当前状态 | 需求目标 |
|---------|---------|---------|
| 路线生成 | 随机打乱POI顺序 | AI多目标优化 |
| POI数据 | 7个固定地标/城市 | 完整POI+评价+实时数据 |
| 偏好理解 | 关键词匹配 | 语义理解+隐含偏好 |
| 个性化 | 无历史记录 | 用户画像+学习 |
| 多方案生成 | 单一路由 | TOP3备选方案 |
| 实时调整 | 静态路线 | 动态更新能力 |

## 2. 功能规划

| 版本 | 重点 | 周期 |

| 版本 | 重点 |

### 2.3 长期演进方向

```
L1: 本地深度游 → 挖掘小众目的地
L2: 跨城市路线 → 串联目的地群
L3: 实时动态调整 → 应对突发状况
L4: 完全自主规划 → 端到端自动化
```

## 3. 技术方案

### 3.1 前端架构优化

| 当前架构 | 推荐方案 |
|---------|---------|
| 单文件HTML | 模块化构建 (Vite) |
| 全局变量管理 | 状态管理 (Zustand/Pinia) |
| 硬编码POI数据 | Deepseek AI Agent 通过 amap-lbs-skill 动态获取 |
| 简单随机算法 | Deepseek AI Agent (Function Calling) 智能规划 |
| 无登录系统 | 用户认证系统 (JWT/OAuth2) |

**前端调用方式变更:**
- 旧：前端直接调用多个 API (POI搜索、路径规划、AI生成)
- 新：前端只调用 `/api/agent/plan`，AI Agent 内部 orchestration

### 3.2 后端扩展方案

**推荐架构: AI Agent 模式（Deepseek 作为规划大脑）**

**关键技术栈:**
- **AI 服务**: Deepseek API with Function Calling (AI 作为规划 Agent)
- **POI 数据**: amap-lbs-skill (高德 Web 服务 API，由 AI Agent 调用)
- **地图渲染**: amap-jsapi-skill (高德 JS API v2.0)
- **用户认证**: JWT Token / OAuth2 第三方登录
- **数据库**: PostgreSQL (用户数据、偏好、历史记录)

**核心设计理念:**
AI 不再只是"生成文本"的工具，而是**规划 Agent** —— 能够：
1. 理解用户模糊需求
2. 主动调用高德 API 获取实时数据
3. 多步推理优化路线
4. 返回结构化旅行规划

### 3.3 API 设计

#### 前端 → AI Agent (单一入口)

##### POST /api/agent/plan

前端只需调用一个 API，AI Agent 自动完成全部规划流程。

**Request:**
```json
{
  "city": "北京",
  "startTime": "2026-05-01 09:00",
  "endTime": "2026-05-01 18:00",
  "preferences": "亲子游, 6岁小孩, 喜欢自然",
  "userId": "u_001"  // 已登录用户的 ID
}
```

**Response:**
```json
{
  "success": true,
  "plan": {
    "routes": [
      {
        "pois": [
          { "name": "颐和园", "arrival": "09:30", "duration": 180, "transport": "步行", "reason": "适合儿童，景色优美，户外空间大" },
          { "name": "北京动物园", "arrival": "13:00", "duration": 150, "transport": "公交", "reason": "孩子喜欢动物，大熊猫是亮点" }
        ],
        "totalDuration": 540,
        "score": 0.92,
        "summary": "本路线适合亲子家庭，包含自然景观和动物观赏..."
      }
    ],
    "alternatives": [...]
  }
}
```

#### 用户认证 API

##### POST /api/auth/register
```json
Request: { "email": "user@example.com", "password": "xxx" }
Response: { "userId": "u_001", "token": "jwt_token" }
```

##### POST /api/auth/login
```json
Request: { "email": "user@example.com", "password": "xxx" }
Response: { "userId": "u_001", "token": "jwt_token", "preferences": {...} }
```

##### GET /api/auth/profile
```json
Header: Authorization: Bearer <token>

```

##### PUT /api/auth/preferences
```json

Response: { "success": true }
```

#### AI Agent 内部工具 (Function Calling)

AI Agent 内部可调用的工具（由 Deepseek Function Calling 实现）:

| 工具名称 | 功能 | 调用高德 API |
|---------|-----|-------------|
| `search_pois` | 搜索 POI 地点 | 高德 POI 搜索 |
| `search_nearby` | 周边搜索 | 高德周边搜索 |
| `geocode` | 地址转坐标 | 高德地理编码 |
| `route_planning` | 路径规划 | 高德路径规划 |
| `get_user_preferences` | 获取用户偏好 | PostgreSQL |

### 3.4 AI Agent 工作流程

```
用户请求
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│                    Deepseek AI Agent                        │
│                                                              │
│  步骤1: 理解意图                                             │
│    - 解析用户输入（城市、时间、偏好）                          │
│    - 获取用户历史偏好（如有）                                 │
│                                                              │
│  步骤2: 搜索 POI                                             │
│    - 调用 search_pois 搜索相关景点                            │
│    - 根据偏好过滤和排序                                       │
│                                                              │
│  步骤3: 路径规划                                             │
│    - 调用 route_planning 计算各站点之间路线                    │
│    - 估算时间和距离                                           │
│                                                              │
│  步骤4: 优化调整                                             │
│    - 检查时间约束是否满足                                      │
│    - 如不满足，调整顺序或精简站点                              │
│    - 如有备选需求，生成替代方案                                │
│                                                              │
│  步骤5: 生成规划                                             │
│    - 整合所有信息                                             │
│    - 生成结构化路线描述                                       │
│    - 添加推荐理由                                             │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
返回结构化旅行规划
```

### 3.5 AI Prompt 与 Function Calling 设计

**Deepseek 系统提示词:**

```
你是一位专业的旅行规划师，擅长根据用户需求规划个性化旅行路线。

你可以通过调用以下工具来完成规划：
- search_pois: 搜索景点、美食、酒店等POI
- search_nearby: 搜索某个位置周边的POI
- geocode: 将地址转换为经纬度坐标
- route_planning: 计算两个位置之间的路线
- get_user_preferences: 获取用户的历史偏好

规划原则：
1. 优先考虑用户明确提出的需求
2. 结合用户历史偏好进行个性化推荐
3. 确保路线时间逻辑合理
4. 提供备选方案应对突发情况

输出格式：
- 路线顺序（景点 + 到达时间 + 停留时长）
- 各站点之间的交通方式
- 推荐理由
- 备选方案（如有）
```

### 3.4 AI Prompt 设计策略

**使用 Deepseek API 进行路线生成**

```
系统角色:
你是一个专业的旅行规划师,熟悉各地景点、美食和文化。
你需要根据用户需求生成个性化路线方案。

输入解析:
- 城市/目的地
- 时间范围(开始/结束)
- 偏好描述(显式+隐式)
- 约束条件(预算、体力、时间)
- 用户历史偏好(登录用户)

输出格式:
- 路线序列(POI顺序)
- 每站推荐理由
- 预计停留时间
- 出行方式建议
- 备选方案

约束处理:
- 冲突时优先考虑用户核心偏好
- 时间不够时给出精简版
- 提供B选项应对高峰
- 结合用户历史偏好进行个性化推荐
```

## 5. 风险与应对

| 风险 | 影响 | 应对策略 |
|-----|-----|---------|
| AI API 调用过多 | 延迟高、成本上升 | 限制调用次数（最多3轮）、结果缓存 |
| Deepseek 幻觉 | 生成不存在的地点 | 严格校验 API 返回数据，过滤无效结果 |
| POI 数据质量 | 推荐不准确 | 多关键词搜索、结果排序优化 |
| 用户隐私 | 数据合规风险 | 脱敏处理、用户授权、JWT 只存必要信息 |
| 高德 API 限流 | 请求失败 | 请求间隔控制、降级到缓存数据 |
